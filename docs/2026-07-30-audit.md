# npm audit review, 2026-07-30

Snapshot of `npm audit` across the repo, with an assessment of what is real and what
is noise. Run on branch `dev-tooling` with uncommitted changes to all three
`package.json` files and their lockfiles.

## Results

| Package                                                  | Total   | Production only |
| -------------------------------------------------------- | ------- | --------------- |
| `backend/`                                               | 25 high | **0**           |
| `frontend/`                                              | 29 high | 3 high          |
| root (extra, since there are three `package.json` files) | 0       | 0               |

The 25/29 counts are badly inflated. `npm audit` counts every intermediate package in a
dependency chain as its own "vulnerability", so a single advisory deep in the tree gets
billed 25 times.

## What is actually wrong

**One dev-only issue, shared by both apps:** `brace-expansion` DoS via unbounded
expansion (CWE-400/770, CVSS 7.5). It arrives through `minimatch` under `jest`, `eslint`,
`typescript-eslint` and `@nestjs/cli`. That single advisory accounts for all 25 backend
findings and 26 of the 29 frontend ones. It is reached only by your own test and lint runs
against your own glob patterns, so there is no attacker-controlled input. Real risk:
negligible.

Worth knowing: it is also **unfixable in place**. Patched releases exist only at
`brace-expansion` 5.0.8/5.0.9, and nothing was backported to the 1.x or 2.x lines that the
installed `minimatch` versions require.

**Three production issues in `frontend/`, all inherited from `next@16.2.12`:**

- `postcss@8.4.31` (nested under `next`): XSS via unescaped `</style>`, plus two
  `sourceMappingURL` path-traversal / file-disclosure advisories.
- `sharp@0.34.5`: inherited libvips CVEs (CVE-2026-33327/33328/35590/35591).

The top-level `@tailwindcss/postcss` already resolves a clean `postcss@8.5.25`. Only
Next.js's own nested copy is stale.

## The important conclusion: do not run `npm audit fix --force`

npm reports `fixAvailable: next@9.3.3` for both production issues. That is a seven-major-version
**downgrade** to a 2020 release. It would destroy the App Router app and pull in vastly more
vulnerability than it resolves. This is a known npm resolver failure mode, not real advice.

Verified: `next@16.2.12` is the **current latest release**. It still pins `postcss@8.4.31`
and `sharp@0.34.5`, while the advisories require `postcss > 8.5.17` and `sharp >= 0.35.0`.
So there is no upstream fix yet, at any version. This is a wait on Vercel, not on us.

Mitigating the exposure further: nothing in `frontend/src/` imports `next/image` or
`<Image>`, so `sharp` is never actually invoked at runtime. And Next's `postcss` runs at
build time over CSS we author, not over user input.

## Recommendation

Accept all of it for now, and treat the CI signal accordingly. Suggested priority:

1. **No action on any of it today.** Zero production-reachable, attacker-facing exposure.
   If an `npm audit` gate is added to `ci.yml`, use `--omit=dev --audit-level=high`, which
   is what makes the backend pass cleanly at 0.
2. **If the counts need to go to zero anyway**, add `overrides` for `postcss` and `sharp`
   in `frontend/package.json`. `sharp@0.35.x` is a safe minor bump; forcing
   `postcss@8.5.25` unifies it with the copy Tailwind already uses. Both need a
   `npm run build` to confirm. Better skipped until a real reason appears.
3. **Watch, do not chase.** Re-audit after the next `next` minor. The `brace-expansion`
   chain clears itself whenever `jest` and `eslint` bump their `minimatch` majors.

If override work does happen, it should land as its own commit rather than being mixed into
the in-flight `dev-tooling` changes.

## Commands used

```bash
# per app, from backend/ and frontend/
npm audit
npm audit --json           # to separate root advisories from transitive noise
npm audit --omit=dev       # the number that actually matters

# to confirm no upstream fix exists
npm ls next sharp postcss --depth=3
npm view next version
npm view sharp version
npm view brace-expansion versions --json
```
